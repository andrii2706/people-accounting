# Як спробувати інтеграцію з 1С без 1С

Тестовий стенд **«Імітація 1С»** (`scripts/fake-1c`) поводиться як база 1С:ЗУП:
- **Як обробка 1С.** Сторінка працює як обробка: тут ви приймаєте, переводите, перейменовуєте і звільняєте працівників, а потім натискаєте «Надіслати працівників».
- **Як опублікована база.** Він також видає себе за опубліковану базу (OData), яку застосунок читає сам.

Так можна пройти весь шлях з обох боків: кадровик у 1С → застосунок → черга повідомлень ТЦК.

У стенді лише вигадані люди. Вносьте тільки вигадані дані й працюйте з локальною базою, не з продакшном.

## Підготовка (один раз)

1. **Запустіть застосунок локально**, як зазвичай:
   ```bash
   cd backend && npm run start:dev     # API: http://localhost:3400 (PORT=3400 у backend/.env)
   cd frontend && npm start            # застосунок: http://localhost:4301
   ```
2. **Запустіть стенд** з кореня репозиторію в окремому терміналі:
   ```bash
   npm run fake:1c                     # або: node scripts/fake-1c/server.mjs
   ```
   Відкрийте **http://localhost:3398**.
3. **Підготуйте юрособу.** Увійдіть у застосунок адміністратором або керівником. Потрібна юрособа з кодом ЄДРПОУ **12345678**: так у стенді названа «ТОВ «Вигадана компанія»». Якщо у вашої юрособи інший код, у стенді в полі «Код ЄДРПОУ організації» оберіть «усі організації».

## Сценарій А: 1С надсилає дані сама

1. **Налаштуйте спосіб.** У застосунку: **Налаштування → юрособа → «Інтеграція з 1С»**.
   - оберіть «1С надсилає дані сама»;
   - зніміть «Застосовувати одразу», щоб спершу переглянути;
   - натисніть **Зберегти**.
2. **Отримайте ключ.** Натисніть **«Видати ключ»**. Скопіюйте ключ (він показується один раз) і адресу `http://localhost:4301/api/integrations/1c/employees`.
3. **Підключіть стенд.** У стенді вставте адресу й ключ → **«Перевірити підключення»**. Має з'явитися «Підключення працює: … (ЄДРПОУ 12345678)».
4. **Надішліть дані.** **«Надіслати працівників»**. Стенд покаже: нових 4, пропущено 1. Павла Давнього звільнили у 2015 році, тож його не додають.
5. **Перегляньте й застосуйте.** У застосунку оновіть сторінку. В «Отриманнях» з'явиться рядок «Чекає на перегляд». Відкрийте його і перевірте список, потім **«Застосувати»**.
   - **Працівники:** з'явилися 4 нові картки. Андрія Чужого немає, він з іншої організації.
   - **Повідомлення ТЦК:** прийняття Олега Тестового, бо його прийнято менше ніж 30 днів тому.
6. **Змініть дані «в 1С».** У стенді:
   - Ірина Вигадана → «Змінити» → прізвище «Заміжня» → «Зберегти в 1С»;
   - Сергій Прикладний → посада «старший водій»;
   - Марія Зразкова → «Звільнити».

   Потім **«Надіслати працівників»**.
7. **Застосуйте зміни.** У застосунку відкрийте нове отримання. У ньому видно, що зміниться:
   - «Прізвище: Вигадана → Заміжня»;
   - «Посада: водій → старший водій»;
   - «Звільнення».

   **«Застосувати»**. У «Повідомленнях ТЦК» — зміна прізвища, посади і звільнення.
8. **Надішліть ще раз без змін.** Стенд покаже «без змін», а отримання закриється само.
9. **Автоматичне застосування.** Увімкніть у застосунку «Застосовувати одразу», змініть щось у стенді й надішліть. Зміни застосуються без перегляду, у журналі картки буде «Інтеграція з 1С».

## Сценарій Б: застосунок читає 1С (OData)

1. **Налаштуйте читання.** У застосунку оберіть «Ми читаємо з 1С (OData)» і введіть:
   - адресу `http://localhost:3398/zup`;
   - користувача `odata`;
   - пароль `secret`.

   Натисніть **Зберегти**. Локально `http` і `localhost` дозволені, на продакшні — лише `https` і зовнішня адреса.
2. **Перевірте з'єднання.** Натисніть **«Перевірити з'єднання»**. Буде видно:
   - конфігурацію «ЗУП / BAS ЗУП»;
   - дві організації;
   - «Працюючих працівників: …».
3. **Отримайте дані.** Змініть щось у стенді → **«Отримати зараз»** → переглянути → «Застосувати».
4. **Щоденне читання.** Поставте «Читати щодня о» на поточну годину, збережіть і запустіть:
   ```bash
   cd backend && npm run job:hr-sync
   ```
   В історії з'явиться «Щоденне читання».

## Разове завантаження

1. **Оберіть «Один раз».** У «Як часто брати дані з 1С» → «Один раз» → Зберегти.
2. **Отримайте дані.** «Отримати зараз» (або «Надіслати працівників» у стенді) → застосуйте. На сторінці з'явиться «Дані з 1С отримано …», а кнопка «Отримати зараз» зникне.
3. **Спробуйте ще раз.** Стенд надсилає ще: протягом години після першого надсилання частини приймаються, пізніше — «Помилка 403: Дані з 1С уже отримано …», і ключ відкликається.
4. **Відкрийте знову.** «Отримати ще раз» дозволяє взяти дані з 1С ще один раз.

## Що ще варто спробувати

| Дія в стенді | Що побачите в застосунку |
|---|---|
| «Прийняти працівника» з датою народження `1990-02-31` | «Помилка в даних», картка не створюється |
| Двом різним працівникам вписати однаковий РНОКПП | «Розбіжність» в обох, нічого не змінюється |
| Неправильний ключ або «Відкликати» ключ у застосунку | У стенді «Помилка 401: Невірний або відкликаний ключ» |
| Пароль `wrong` в OData | «1С не прийняла логін або пароль» |
| «Видалити» працівника в стенді | У застосунку нічого не видаляється: картки знімає лише звільнення |
| «Військові дані з 1С» = замінювати / не брати | Звання і ВОС Сергія Прикладного беруться або не беруться |

**«Скинути дані»** у стенді повертає початкових людей, адреса й ключ зберігаються. Дані стенду лежать у `scripts/fake-1c/data.json`, у git цей файл не потрапляє.

Як підключити справжню BAS, описано в [1C.md](1C.md).
