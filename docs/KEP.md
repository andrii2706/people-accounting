# Підпис листів КЕП

Лист до ТЦК (повідомлення про зміни, списки, відомість) можна підписати **кваліфікованим електронним
підписом будь-якого надавача** і надіслати пакетом «документ + підпис».

## Як це працює

```
1. Зафіксувати документ      .docx генерується один раз → сховище (write-once) + SHA-256
                              реквізити листа більше не змінюються
2. Підписати                  а) віджетом ІІТ прямо на сторінці листа
                              б) будь-якою програмою → завантажити файл .p7s
3. Перевірка на сервері       підпис саме під цей документ? (хеш) → дані сертифіката → збереження
4. Відправка                  email: документ + .p7s;  або «Пакет для ТЦК (.zip)» для іншого каналу
```

Формат — **CAdES, окремий (detached) підпис `.p7s`** до файлу `.docx`. Такий пакет перевіряється
на [czo.gov.ua/verify](https://czo.gov.ua/verify) і будь-якою програмою КЕП. Кілька підписів
(наприклад, керівник і відповідальна особа) — кілька файлів `.p7s` до того самого документа.

## Спосіб А: файл .p7s з будь-якої програми (працює завжди)

1. На сторінці листа: **Підпис КЕП → Зафіксувати документ для підпису → Файл для підпису**.
2. Підпишіть файл у звичній програмі, обравши *окремий файл підпису / CAdES / .p7s*:
   * **Дія.Підпис** — [id.gov.ua/sign](https://id.gov.ua/sign) (смартфон, без файлового ключа);
   * **ЦЗО** — [czo.gov.ua/sign](https://czo.gov.ua/sign) (файловий ключ, токен, хмарний КЕП);
   * «ІІТ Користувач ЦСК», «Вчасно», M.E.Doc, Medoc/Sota, ПриватБанк SmartID тощо.
3. **Додати файл .p7s** — сервер перевірить і покаже, хто підписав.

Підтримуються DER, base64 і PEM; підпис із вкладеними даними (`.p7m`) теж приймається, якщо всередині саме цей документ.

## Спосіб Б: віджет ІІТ на сторінці (зручніше для щоденної роботи)

Віджет «Підпис» від ІІТ відкривається у фреймі з сайту ІІТ і підтримує файлові ключі всіх кваліфікованих
надавачів, захищені носії («Алмаз-1К», «Кристал-1», SecureToken — через агент ІІТ) і хмарні КЕП
(перелік визначає ІІТ). Ключ і пароль обробляються у фреймі ІІТ — застосунок їх не отримує.

Налаштування:

1. Завантажте пакет віджета з сайту ІІТ (розділ «Бібліотеки підпису → Віджет підпису») і покладіть
   `eusign.js` у `frontend/public/iit/eusign.js` (файл стане доступним як `/iit/eusign.js`).
2. Задайте змінні API (локально — `backend/.env`, продакшн — змінні GitHub):
   ```
   SIGN_WIDGET_SCRIPT_URL=/iit/eusign.js
   SIGN_WIDGET_FRAME_URL=https://eu.iit.com.ua/sign-widget/v20240301/   # актуальна версія — у документації ІІТ
   ```
3. Якщо адреса фрейму на іншому домені — додайте його в `CSP_FRAME_SRC` (`frontend/apphosting.yaml`).

Без цих змінних вкладка віджета не показується — лишається спосіб А.

Адаптер: `frontend/src/app/shared/services/iit-sign-widget.service.ts` (`EndUser`, `ReadPrivateKey`,
`SignData(data, external=true, base64=true, алгоритм за типом ключа, CAdES-X Long)`).
API віджета належить ІІТ — після оновлення його версії перевірте назви констант у їхній документації.

## Що перевіряє сервер

`backend/src/signatures/cms.ts`:

| Перевірка | ДСТУ 4145 (класичні ключі) | ECDSA / RSA |
|---|---|---|
| Структура CMS, сертифікат підписувача (ПІБ, посада, організація, ЄДРПОУ, строк дії) | ✅ | ✅ |
| Підпис зроблено **саме під цей документ** (messageDigest = хеш файлу) | ✅ ГОСТ 34.311 | ✅ SHA-2 |
| Криптографічна перевірка підпису | — | ✅ |
| Ланцюжок до кваліфікованого надавача, OCSP/CRL | — | — |

Статуси: **Підпис дійсний** (ECDSA/RSA перевірено повністю), **Документ збігається** (ДСТУ: хеш збігся;
остаточна юридична перевірка — czo.gov.ua і програма отримувача), **Не перевірено** (невідомий алгоритм,
напр. ДСТУ 7564 «Купина» — перевіряйте на czo.gov.ua).

Підпис під інший документ, пошкоджений файл або «чужий» ключ під сертифікатом відхиляються одразу.
РНОКПП власника ключа з сертифіката зберігається лише замаскованим (`••••••1234`).

## Незмінність

* Документ і підписи пишуться у сховище лише один раз (локально — `wx`, у GCS — `ifGenerationMatch=0`),
  бакет має retention policy.
* Перед кожною видачею документ звіряється з SHA-256.
* Таблиця `letter_signatures` захищена тригером від змін і видалення.
* Підписаний лист не можна редагувати чи видалити; скасувати фіксацію можна лише до першого підпису.
* Кожен підпис потрапляє в журнал дій (`SIGN`).

## Тестування без справжнього КЕП

```bash
cd backend
npm run dev:sign -- "/шлях/до/Повідомлення 12.docx"   # → "…docx.p7s", тестовий ECDSA (НЕ КЕП)
```

Отриманий файл можна завантажити на сторінці листа — він пройде перевірку зі статусом «Підпис дійсний»,
а в даних сертифіката буде «ТЕСТОВИЙ надавач (не КЕП)».
