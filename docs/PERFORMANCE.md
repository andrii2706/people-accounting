# Продуктивність фронтенду

Тест від 03.11.2026. Локальна копія бази з **1015 працівниками** (вигадані дані, `scripts/perf/seed.mjs`),
production-збірка з SSR. Сценарій роботи — Playwright з процесором, сповільненим у 4 рази
(звичайний офісний ноутбук); Lighthouse — десктоп і мобільний профіль.

## Що знайдено й виправлено

| Проблема | Наслідок | Виправлення |
|---|---|---|
| Таблиця працівників малювала всі рядки одразу | 32 000 DOM-вузлів, 2 с блокування інтерфейсу | Рядки порціями по 100, наступна порція — при прокрутці до кінця |
| Списки (Дод. 5) так само | 28 000 вузлів, 5,6 с | Порції по 100 у кожному списку |
| Angular SSR приймає від API не більше 1 МБ | Від ~700 працівників сторінка «Працівники» при оновленні перекидала на «Огляд» | Ліміт для SSR піднято до 16 МБ; список не несе текстів попереджень (лише код і рівень) — 1,5 МБ → 0,8 МБ |
| Відповіді не стискалися | 2,5 МБ на відкриття списку | gzip у SSR-сервері (сторінки, статика, API) — 63–107 КБ |
| Сповіщення (до 1 МБ) перезавантажувалися на кожному переході | Зайвий трафік і робота | Не частіше разу на хвилину; на «Огляді» — завжди свіжі |
| Вкладки «Відстрочка / Заброньовані / Потребують уваги» заново завантажували весь список | 2,2 с на перемикання | Вкладки фільтрують уже завантажений список |
| Кеш статики не впізнавав нові імена файлів і шрифти | Повторне завантаження JS і шрифтів через годину | Файли з хешем (JS, CSS, woff2) кешуються на рік |

## Lighthouse (після)

| Сторінка | Десктоп: продуктивність / доступність | Мобільний: продуктивність |
|---|---|---|
| Вхід | 100 / 100 | 80 |
| Огляд | 100 / 100 | 93 |
| Працівники (1015) | 98 / 100 | 63 |
| Картка | 99 / 100 | 71 |
| Списки (Дод. 5) | 93 / 100 | 68 |

Початкове завантаження — 124 КБ (стиснуто), найбільша сторінка (картка) додає 18 КБ.
Мобільний профіль (повільний 4G + CPU ×4) на великих сторінках упирається в розбір даних, переданих
із сервера; застосунок розрахований на роботу з комп'ютера.

## Як повторити

```bash
# локальна копія бази — ніколи не запускати на продакшн-даних
createdb -T military military_perf
DATABASE_URL=postgres://…/military_perf npm run start:prod   # backend
npm run build && npm run serve:ssr                           # frontend

cd scripts/perf
npm install
npm run seed         # +1000 вигаданих працівників
npm run ui           # сценарій роботи, CPU ×4
npm run lighthouse   # десктоп і мобільний
```
Змінні `PERF_APP`, `PERF_API`, `PERF_EMAIL`, `PERF_PASSWORD` — адреси й обліковий запис (див. `config.mjs`).
