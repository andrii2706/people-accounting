# Безпека

Застосунок обробляє персональні дані особливої чутливості: РНОКПП, паспортні дані, військово-облікові
документи, склад сім'ї. Нижче — що саме захищено і де це в коді.

## Модель загроз (коротко)

| Загроза | Захист |
|---|---|
| Доступ сторонніх з інтернету | API без публічного доступу (Cloud Run IAM); лише SSR-сервер з токеном свого сервісного акаунта. Необов'язково — `ALLOWED_CLIENT_CIDRS` (лише офіс/VPN) |
| Підбір пароля | 5 спроб/хв з IP, блокування облікового запису після 5 помилок на 15 хв, політика паролів (≥ 12 символів, літери й цифри, без частини email), IP у журналі |
| Викрадення сесії | httpOnly + Secure + SameSite=Lax cookie `__Host-mr_session`, недоступна JS; сесія закінчується після 30 хв бездіяльності і через 10 год у будь-якому разі; відкликання при зміні пароля/блокуванні (`tokenVersion`, перевіряється в БД на кожен запит) |
| CSRF | SameSite cookie + перевірка `Sec-Fetch-Site` / `Origin` для всіх змінюючих запитів |
| XSS | Angular екранує шаблони; CSP: `script-src 'self'` + SHA-256 хеші інлайн-скриптів SSR (обчислюються на кожну відповідь), `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'` |
| Клікджекінг | `frame-ancestors 'none'`, `X-Frame-Options: DENY` |
| Витік з бекапу / дампу БД | РНОКПП, номери паспортів, військово-облікових документів, реєстраційний номер — **AES-256-GCM** на рівні застосунку; пошук за РНОКПП — через HMAC «сліпий індекс». Cloud SQL додатково шифрує диск |
| Витік через кеш / проксі | `Cache-Control: no-store` для API і SSR-сторінок, `private` |
| Витік через журнали | чутливі поля маскуються в `audit_log` (`•••12`); паролі не логуються |
| Внутрішній порушник | журнал дій: вхід/вихід, **перегляд картки**, зміни (до/після), експорт документів, надсилання, підпис КЕП — з ім'ям користувача й часом |
| Підміна підписаного документа | документ фіксується (SHA-256) перед підписом; файли — write-once (GCS precondition + retention policy); таблиця підписів захищена тригером від UPDATE/DELETE |
| SSRF / Host header | `NG_ALLOWED_HOSTS` (Angular SSR), проксі лише на фіксований `API_INTERNAL_URL`, клієнтські `X-Forwarded-*` і `X-Serverless-Authorization` перезаписуються |
| Ланцюг постачання | `npm audit` у CI, Dependabot, фіксовані lock-файли, образи в приватному Artifact Registry |
| Компрометація CI | Workload Identity Federation без ключів; токен лише для `main` + environment `production` з ручним підтвердженням; деплойер не має доступу до секретів і БД |

## Ролі

* `ADMIN` — усе, включно з користувачами (створення, блокування, скидання пароля, розблокування) і налаштуваннями.
* `HR` — робота з працівниками, листами, звітами, підписом.

Новий користувач і скинутий пароль → тимчасовий пароль, який треба змінити при першому вході
(до зміни доступний лише профіль).

## Шифрування полів

`backend/src/common/crypto/field-encryption.ts` — формат `enc:v1:<iv>:<tag>:<ciphertext>` (base64url).
Ключі: `DATA_ENCRYPTION_KEY`, `BLIND_INDEX_KEY` (Secret Manager). Без ключа дані в БД не прочитати —
**зберігайте ключі так само надійно, як бекапи** (Secret Manager не дає видалити версію випадково,
але вимкнення/знищення версії = втрата даних).

## IP клієнта за проксі

Ланцюжок у продакшні: браузер → балансувальник Google → SSR (App Hosting) → Google front end → API.
SSR визначає IP за `TRUST_PROXY_HOPS` (за замовчуванням 2 в `apphosting.yaml`) і сам формує
`X-Forwarded-For` для API (клієнтський заголовок відкидається); API — `TRUST_PROXY_HOPS=2`.
Після першого деплою перевірте: у `audit_log` для `LOGIN` поле `ip` має бути вашою публічною адресою.
Якщо там адреса Google — збільште значення на 1 (і навпаки, якщо можна підставити довільну через `X-Forwarded-For`).

## Чек-лист перед запуском

- [ ] `infra/bootstrap.sh` виконано, змінні GitHub заповнені, environment `production` з reviewers.
- [ ] `gcloud run services get-iam-policy military-registry-api` — немає `allUsers`/`allAuthenticatedUsers`.
- [ ] Відкриття URL API напряму → 403.
- [ ] Перший вхід адміністратора → примусова зміна пароля.
- [ ] `ALLOWED_CLIENT_CIDRS` — якщо робота лише з офісу/VPN.
- [ ] Власний домен + HSTS (заголовок уже надсилається).
- [ ] Retention бакета підписів — за потреби заблокуйте (`--lock-retention-period`, незворотно).
- [ ] Наказ про обробку персональних даних, перелік осіб з доступом = список користувачів застосунку.
- [ ] Тестові середовища — лише з демо-даними (`npm run seed -- --demo`), ніколи з реальними.
