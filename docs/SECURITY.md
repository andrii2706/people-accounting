# Безпека

Застосунок обробляє персональні дані особливої чутливості: РНОКПП, паспортні дані, військово-облікові
документи, склад сім'ї. Нижче — що саме захищено і де це в коді.

## Модель загроз (коротко)

| Загроза | Захист |
|---|---|
| Доступ сторонніх з інтернету | API без публічного доступу (Cloud Run IAM); лише SSR-сервер з токеном свого сервісного акаунта. Необов'язково — `ALLOWED_CLIENT_CIDRS` (лише офіс/VPN) |
| Вкрадений або підібраний пароль | **Вхід з кодом із телефону** (TOTP, RFC 6238) — для всіх ролей за замовчуванням (`MFA_REQUIRED_ROLES`). Після пароля видається лише квиток на 5 хв, сесію — тільки після коду. Секрет застосунку зашифровано AES-GCM, той самий код двічі не приймається, 5 неправильних кодів → блокування й лист «хтось знає ваш пароль». 10 резервних кодів (зберігаються лише хеші) |
| Підбір пароля | 20 спроб/хв з IP, блокування облікового запису після 5 помилок на 15 хв, політика паролів (≥ 12 символів, літери й цифри, без частини email), IP у журналі |
| Викрадення сесії | httpOnly + Secure + SameSite=Lax cookie `__Host-mr_session`, недоступна JS; сесія закінчується після 30 хв бездіяльності і через 10 год у будь-якому разі; відкликання при зміні пароля/блокуванні (`tokenVersion`, перевіряється в БД на кожен запит) |
| CSRF | SameSite cookie + перевірка `Sec-Fetch-Site` / `Origin` для всіх змінюючих запитів |
| XSS | Angular екранує шаблони; CSP: `script-src 'self'` + SHA-256 хеші інлайн-скриптів SSR (обчислюються на кожну відповідь), `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'` |
| Клікджекінг | `frame-ancestors 'none'`, `X-Frame-Options: DENY` |
| Витік з бекапу / дампу БД | РНОКПП, номери паспортів, військово-облікових документів, реєстраційний номер — **AES-256-GCM** на рівні застосунку; пошук за РНОКПП — через HMAC «сліпий індекс». Cloud SQL додатково шифрує диск |
| Витік через кеш / проксі | `Cache-Control: no-store` для API і SSR-сторінок, `private` |
| Витік через журнали | чутливі поля маскуються в `audit_log` (`•••12`); паролі не логуються |
| Масовий витік даних | **ліміт вивантажень** (60 файлів/год, 300/добу на обліковий запис, `EXPORT_LIMIT_PER_*`); кожен файл записано з SHA-256 — «Безпека → Хто вивантажив файл?» знаходить, хто й коли його взяв; у властивостях Word/Excel — поле «Вивантаження» (№, ім'я, час). Документ під КЕП не змінюється ніколи. Понад 200 переглядів карток за годину — лист керівникам |
| Шкідливі файли | **кожен завантажений файл перевіряється до читання**: справжній тип за вмістом, без програм, макросів (vbaProject, XLM), ActiveX, OLE-об'єктів, зовнішніх шаблонів і посилань (UNC, `mhtml:`, attachedTemplate), полів DDE/INCLUDETEXT, формул-команд у CSV, скриптів/HTML/SVG, JavaScript у PDF, «zip-бомб» (`security/utils/file-safety.utils.ts`). Небезпечний файл — у журнал безпеки й лист керівникам |
| Атаки з інтернету на сторінки | **Cloud Armor** (`infra/cloud-armor.sh`): правила OWASP, ліміт запитів з адреси (вхід — 30/хв, бан 15 хв), лише дозволені країни; щотижневе сканування OWASP ZAP копії застосунку в CI (`.github/workflows/security-scan.yml`) |
| Вкрадений ключ 1С | дозволені IP-адреси сервера 1С і строк дії ключа (30 днів – рік); спроба з чужої адреси — 403 і лист |
| Внутрішній порушник | журнал дій: вхід/вихід, **перегляд картки**, зміни (до/після), експорт документів, надсилання, підпис КЕП — з ім'ям користувача й часом |
| Підміна підписаного документа | документ фіксується (SHA-256) перед підписом; файли — write-once (GCS precondition + retention policy); таблиця підписів захищена тригером від UPDATE/DELETE |
| SSRF / Host header | `NG_ALLOWED_HOSTS` (Angular SSR), проксі лише на фіксований `API_INTERNAL_URL`, клієнтські `X-Forwarded-*` і `X-Serverless-Authorization` перезаписуються |
| Ланцюг постачання | `npm audit` у CI, Dependabot, фіксовані lock-файли, образи в приватному Artifact Registry |
| Компрометація CI | Workload Identity Federation без ключів; токен лише для `main` + environment `production` з ручним підтвердженням; деплойер не має доступу до секретів і БД |

## Журнал безпеки і сповіщення

Налаштування → «Безпека» (адміністратори юрособи, директор, головний адміністратор). Що записується і кому лист:

| Подія | Рівень | Лист |
|---|---|---|
| Вхід заблоковано після 5 невдалих паролів | Увага | людині й керівникам |
| Підбір паролів з однієї адреси (≥ 20 невдач у ≥ 3 облікові записи за 10 хв) | Небезпечно | головним адміністраторам |
| Вхід з нового пристрою (браузера) | До відома | людині |
| Правильний пароль, але 5 неправильних кодів | Небезпечно | людині й керівникам |
| Код увімкнено / вимкнено / скинуто адміністратором, вхід резервним кодом, нові коди | До відома / Увага | людині (вимкнення й скидання — і керівникам) |
| Ліміт вивантажень, масовий перегляд карток | Небезпечно / Увага | керівникам |
| Заблоковано небезпечний файл | Небезпечно | керівникам |
| Ключ 1С з чужої адреси або прострочений | Увага | керівникам |

Повтор того самого за годину не створює нового листа (а для хвиль — нового рядка, лише «повторів: N»).
Без `SMTP_URL` листи не йдуть, але журнал ведеться. Додаткові адреси — `SECURITY_ALERT_EMAILS`.
Журнал зберігається рік (щоденне завдання видаляє старіші записи).

## Вхід з кодом: що робити, якщо…

* **Новий телефон / загубили телефон, але є резервні коди** — увійти резервним кодом, у профілі створити нові коди;
  налаштувати застосунок наново: адміністратор «⋯ → Скинути вхід з кодом», під час наступного входу — новий QR.
* **Немає ні телефона, ні кодів** — адміністратор юрособи «Скинути вхід з кодом»; усі сесії людини завершуються.
* **Головний адміністратор без телефона й кодів** — у базі (лише з доступом до Cloud SQL):
  `UPDATE users SET "mfaSecret"=NULL, "mfaEnabledAt"=NULL, "mfaRecoveryHashes"='[]', "tokenVersion"="tokenVersion"+1 WHERE email='…';`
* **Локальні перф-скрипти** — API з `MFA_REQUIRED_ROLES=none` (лише локально).

## Ролі

* `ADMIN` — головний адміністратор: усі юрособи, користувачі, налаштування, журнал безпеки всіх юросіб.
* `ENTITY_ADMIN`, `DIRECTOR` — своя юрособа: користувачі (зокрема скидання входу з кодом), журнал безпеки юрособи.
* `HR` — робота з працівниками, листами, звітами, підписом.

Новий користувач і скинутий пароль → тимчасовий пароль, який треба змінити при першому вході
(до зміни доступний лише профіль).

## Шифрування полів

`backend/src/common/crypto/field-encryption.ts` — формат `enc:v1:<iv>:<tag>:<ciphertext>` (base64url).
Ключі: `DATA_ENCRYPTION_KEY`, `BLIND_INDEX_KEY` (Secret Manager). Без ключа дані в БД не прочитати —
**зберігайте ключі так само надійно, як бекапи** (Secret Manager не дає видалити версію випадково,
але вимкнення/знищення версії = втрата даних).

## IP клієнта за проксі

Ланцюжок у продакшні: браузер → балансувальник Google → SSR (App Hosting) → Google front end → API.
SSR визначає IP за `TRUST_PROXY_HOPS` (за замовчуванням 2 в `apphosting.yaml`) і сам формує
`X-Forwarded-For` для API (клієнтський заголовок відкидається); API — `TRUST_PROXY_HOPS=2`.
Після першого деплою перевірте: у `audit_log` для `LOGIN` поле `ip` має бути вашою публічною адресою.
Якщо там адреса Google — збільште значення на 1 (і навпаки, якщо можна підставити довільну через `X-Forwarded-For`).

## Чек-лист перед запуском

- [ ] `infra/bootstrap.sh` виконано, змінні GitHub заповнені, environment `production` з reviewers.
- [ ] `gcloud run services get-iam-policy military-registry-api` — немає `allUsers`/`allAuthenticatedUsers`.
- [ ] Відкриття URL API напряму → 403.
- [ ] Перший вхід адміністратора → примусова зміна пароля.
- [ ] `ALLOWED_CLIENT_CIDRS` — якщо робота лише з офісу/VPN.
- [ ] Головний адміністратор увійшов і налаштував вхід з кодом; резервні коди — у сейфі / менеджері паролів.
- [ ] `SMTP_URL` налаштовано — інакше листи безпеки не приходять (журнал усе одно ведеться).
- [ ] `infra/cloud-armor.sh` — тиждень у режимі перегляду, потім `WAF_PREVIEW=false`, потім `LOCK_INGRESS=true`.
- [ ] Ключ 1С — з дозволеними адресами сервера 1С і строком дії.
- [ ] Workflow «Security scan (ZAP)» пройшов без FAIL.
- [ ] Зовнішній тест на проникнення (pentest) перед підключенням перших клієнтів.
- [ ] Власний домен + HSTS (заголовок уже надсилається).
- [ ] Retention бакета підписів — за потреби заблокуйте (`--lock-retention-period`, незворотно).
- [ ] Наказ про обробку персональних даних, перелік осіб з доступом = список користувачів застосунку.
- [ ] Тестові середовища — лише з демо-даними (`npm run seed -- --demo`), ніколи з реальними.
