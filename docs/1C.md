# Інтеграція з 1С / BAS

Працівники приходять у «Військовий облік» з облікової системи компанії: 1С:ЗУП, BAS ЗУП або BAS Бухгалтерія / Комплексне.

Що переноситься:
- нові працівники;
- зміни ПІБ і посади;
- звільнення.

Що відбувається з картками:
- 1С — головне джерело кадрових даних, тому її значення замінює наше;
- порожнє значення з 1С наших даних не стирає;
- зміни, про які треба повідомити ТЦК (прийняття, звільнення, зміна ПІБ чи посади), стають у звичайну чергу повідомлень.

Налаштування: **Налаштування → Юрособа → «Інтеграція з 1С»** (`/settings/legal-entities/:id/1c`).

**Спробувати без 1С** можна на тестовому стенді `npm run fake:1c`. Покрокова інструкція — у [1C-TEST.md](1C-TEST.md).

## Три способи

| Спосіб | Коли обрати | Що потрібно |
|---|---|---|
| **1С надсилає сама** (рекомендовано) | 1С стоїть в офісі чи на сервері без публікації в інтернет | Зовнішня обробка в 1С (файли в `frontend/public/1c/`) і ключ зі сторінки налаштувань |
| **Ми читаємо OData** | База 1С уже опублікована на веб-сервері з HTTPS | Адреса публікації, окремий користувач 1С лише з правом читання |
| **Файл** | Разово або без доступу до 1С | Звіт з 1С у Excel → «Працівники → Імпорт» |

Хто що робить:
- **Керівник або адміністратор юрособи:** налаштовує підключення і видає ключ.
- **Кадровик:** отримує дані, переглядає їх і застосовує.

## Що відбувається з даними

Кожне надходження з 1С (надіслане або прочитане) стає **отриманням**. Кожного працівника з отримання порівнюємо з нашими картками і шукаємо в такому порядку:

1. за кодом у 1С (`externalId`, `Ref_Key` працівника);
2. за РНОКПП (blind index, без розшифрування);
3. за ПІБ і датою народження.

| Дія | Що означає |
|---|---|
| Новий | Такої людини ще немає: картка створюється. Повідомлення ТЦК про прийняття — лише якщо дата прийняття в межах останніх 30 днів. |
| Зміни | Кадрові поля з 1С відрізняються від наших. Нова посада стає новим записом у списку посад від сьогодні. |
| Звільнення | У 1С є дата звільнення. Звільнення ставиться в картку, повідомлення стає в чергу ТЦК. |
| Без змін | Нічого робити не треба. Код у 1С тихо зберігається в картці, якщо його ще не було. |
| Пропущено | Людину давно звільнено (і не ввімкнено «Додавати й звільнених»), або це друге місце роботи тієї самої особи. |
| Помилка в даних | Значення з 1С не проходить ті самі перевірки, що й форма картки (дата, РНОКПП, ПІБ). |
| Розбіжність | Неоднозначний збіг, наприклад РНОКПП з 1С належить іншій картці. Нічого не змінюється, вирішує людина. |

Як застосовуються зміни:
- **«Застосовувати одразу»:** зміни застосовуються автоматично. В журналі картки й у черзі ТЦК записано «Інтеграція з 1С».
- **Без цього параметра:** отримання чекає на кнопку «Застосувати» або «Відхилити».
- **Перед застосуванням** дані ще раз порівнюються з картками в їхньому поточному стані.

**Військові дані** (звання, ВОС, ТЦК, придатність, документ) беруться з 1С за налаштуванням:
- заповнювати лише порожні (типово);
- замінювати;
- не брати.

Отримання зберігаються зашифрованими і видаляються через **30 днів** щоденною задачею.

## Спосіб 1: 1С надсилає дані

### Протокол

```
POST https://<домен>/oblik/api/integrations/1c/employees
Authorization: Bearer mr1c_xxxxxxxx_<43 символи>
Content-Type: application/json; charset=utf-8

{ "employees": [ { … }, … ] }      ← не більше 500 за запит, більший список — частинами
```

Поля працівника. Усі поля — рядки. Дати — `РРРР-ММ-ДД` або `ДД.ММ.РРРР`. Порожні й відсутні поля нічого не стирають.

| Поле | Що це |
|---|---|
| `externalId` | Унікальний ідентифікатор працівника в 1С (найнадійніше зіставлення) |
| `personnelNumber` | Табельний номер |
| `lastName`, `firstName`, `middleName` | ПІБ окремо (або `fullName` одним рядком) |
| `rnokpp`, `birthDate`, `gender` (`M`/`F`) | |
| `phone`, `email`, `registeredAddress`, `actualAddress` | |
| `passport`, `passportIssuedBy`, `passportIssuedAt` | `АА 123456` або 9 цифр ID-картки |
| `position`, `department` | Поточна посада і підрозділ |
| `hireDate`, `hireOrderNumber`, `hireOrderDate` | |
| `dismissalDate`, `dismissalOrderNumber`, `dismissalOrderDate` | |
| `military` | Необов'язково, див. нижче |

Об'єкт `military`:
- `registered` (так/ні або назва ТЦК);
- `rank` (текстом, наприклад «старший солдат»);
- `vos`, `registryNumber`, `fitness`, `fitnessDate`;
- `tck` (назва — зіставляється з довідником);
- `servedInArmy`;
- `document` з полями `type`, `series`, `number`, `issuedBy`, `issuedAt`.

### Відповідь

У відповіді `200 OK`:

```json
{ "batchId": "…", "received": 120, "status": "APPLIED",
  "counts": { "total": 120, "create": 2, "update": 5, "dismiss": 1, "unchanged": 112, "skip": 0, "error": 0, "conflict": 0 } }
```

Помилки:
- `400` — невірний формат, текст пояснює, що саме не так;
- `401` — невірний або відкликаний ключ;
- `403` — спосіб не «1С надсилає» або підписка неактивна;
- `429` — забагато запитів: 30 на хвилину на адресу.

Перевірка ключа: `GET …/integrations/1c/ping` з тим самим заголовком → `{ ok, legalEntity, edrpou }`.

### Обробка для 1С (ЗУП 3 / BAS ЗУП)

Файли лежать у `frontend/public/1c/`. Вони ж завантажуються зі сторінки налаштувань.

- `oblik-1c-export.bsl` — модуль об'єкта:
  - реєстрація в БСП;
  - команда за розкладом;
  - запит до `Сотрудники`, `ТекущиеКадровыеДанныеСотрудников`, `ФИОФизическихЛиц`;
  - надсилання частинами по 500;
  - перевірка ключа.
- `oblik-1c-export-form.bsl` — модуль форми налаштувань.

Як скласти обробку (Конфігуратор):

1. **Створити обробку.** Файл → Новий → Зовнішня обробка. Ім'я `ВійськовийОблік_Надсилання`.
2. **Модуль об'єкта.** Вставити текст `oblik-1c-export.bsl`.
3. **Форма.** Створити основну форму обробки:
   - **реквізити:**
     - `Адреса`, `Ключ`, `КодЄДРПОУ` — рядок;
     - `ДополнительнаяОбработка` — `СправочникСсылка.ДополнительныеОтчетыИОбработки`;
   - **поле «Ключ»:** режим пароля;
   - **команди:** `Зберегти`, `ПеревіритиПідключення`, `НадіслатиЗараз`;
   - **модуль форми:** вставити текст `oblik-1c-export-form.bsl`.
4. **Зберегти обробку.** Зберегти як `.epf`.

Як підключити в 1С (Підприємство):

1. **Додати обробку.** Адміністрування → Друк, звіти та обробки → **Додаткові звіти та обробки** → Додати з файлу.
2. **Дозволити небезпечний режим.** Небезпечний режим потрібен для HTTPS-з'єднання.
3. **Налаштувати підключення.** Команда «Налаштування підключення» → вставити:
   - **адресу** — її показує сторінка «Інтеграція з 1С»;
   - **ключ**;
   - **код ЄДРПОУ** — якщо в базі кілька організацій.

   Налаштування зберігаються в безпечному сховищі 1С.
4. **Перевірити.** Натиснути «Перевірити підключення», потім «Надіслати зараз».
5. **Розклад.** У картці обробки → команда «Надіслати працівників» → **Розклад**, наприклад щодня о 06:00.

Для **BAS Бухгалтерія / Комплексне** в запиті замініть:
- `Сотрудники` → `СотрудникиОрганизаций`;
- кадрові дані — на реквізити працівника: `Должность`, `ПодразделениеОрганизации`, `ДатаПриемаНаРаботу`, `ДатаУвольнения`.

Військові дані з регістра військового обліку конфігурації програміст 1С додає в поле `military` за форматом вище.

## Спосіб 2: читання OData

1. **Опублікувати базу.** Опублікуйте базу на веб-сервері (Apache або IIS) **з HTTPS**. Позначте «Публікувати стандартний інтерфейс OData».
2. **Вибрати таблиці.** У 1С: обробка «Налаштування автоматичного REST-сервісу» (`НастройкаАвтоматическогоRESTСервиса`) або `УстановитьСоставСтандартногоИнтерфейсаOData`. Додайте до складу:
   - ЗУП:
     - довідники `Сотрудники`, `ФизическиеЛица`, `Организации`, `Должности`, `ПодразделенияОрганизаций`;
     - регістри відомостей `ТекущиеКадровыеДанныеСотрудников`, `ФИОФизическихЛиц`;
   - BAS Бухгалтерія: `СотрудникиОрганизаций`, `ФизическиеЛица`, `Организации`, `ДолжностиОрганизаций`, `ПодразделенияОрганизаций`, `ФИОФизЛиц`.

   Українські назви (BAS) теж розпізнаються.
3. **Створити користувача.** Окремий користувач 1С з роллю лише на читання цих об'єктів.
4. **Налаштувати сторінку.** На сторінці «Інтеграція з 1С» вкажіть адресу публікації (`https://1c.company.ua/zup`), користувача і пароль, потім «Перевірити з'єднання». Перевірка покаже:
   - розпізнану конфігурацію;
   - організації бази;
   - кількість працюючих;
   - які таблиці не опубліковано.

Правила підключення:
- **Протокол:** лише `https://`.
- **Адреса:** внутрішні адреси (10.x, 192.168.x, localhost) не приймаються.
- **DNS:** адреса перевіряється один раз і закріплюється на час з'єднання, підмінити її через DNS не вийде.

Обмеження читання:
- **Обсяг:** до 5000 працівників і 50 МБ відповіді.
- **Тайм-аут:** 30 с на запит.

**Розклад.** Cloud Run Job `military-registry-hr-sync` запускається щогодини о :05. Він читає юрособи, у яких настала обрана година за Києвом. Щоденна задача підстраховує: дочитує тих, кого не читали понад добу, і видаляє отримання старші за 30 днів.

## Безпека

- **Ключ надсилання.** Показується один раз. У базі зберігається лише SHA-256 його секретної частини, порівняння — за сталий час. Новий ключ одразу скасовує попередній. Будь-яку дію з ключем записано в журнал юрособи.
- **Пароль OData.** Зашифрований (AES-256-GCM, `DATA_ENCRYPTION_KEY`), назад не показується.
- **Отримання.** Зміст отримань (ПІБ, РНОКПП) зберігається зашифрованим. Перегляд отримання записується в журнал.
- **Шлях запиту.** Запит 1С проходить через шлюз застосунку. API ззовні недоступний, Cloud Run IAM передається в `X-Serverless-Authorization`, тому заголовок `Authorization` вільний для ключа 1С.
- **CSRF.** Захист пропускає серверні запити без `Origin`. Перевіркою тут є ключ.
- **Дані для перевірки.** Перевіряйте лише на локальній базі з вигаданими людьми.
